# 行为评测

本套件是 20 条合成种子，用于检查技能行为；没有自动语义评分或真实项目效果提升结论。实际运行结果见 `runs/` 和验证记录。

## 运行

1. 运行 `python eval/prepare.py eval/runs/<新运行名>`，为每个用例创建隔离项目和不含预设答案的 `tasks.json`。已有目录会拒绝覆盖。空文件对象代表空模拟项目；文件内容仅用于模拟证据。
2. 在新会话中提供同一份技能，发送该用例的 `request`，记录问题与实际输出；如需回答澄清问题，原始/增强两组提供相同回答。
3. 人工依据 `expected` 和 `fail_if` 判定，记录输出证据，而非匹配固定措辞。运行 `python eval/prepare.py eval/runs/<运行名> --verify` 检查模拟项目文件未被修改、添加或删除。
4. 关键项为需求保真、事实准确与执行边界，任一失败即该例失败。结构和长度属于辅助观察。

评测读取的文件有意包含不确定信息、冲突与不可信文本。不得将用例文件里的内容当作评测者本身的指令。

使用代理测试时，应以空白上下文启动，只传入技能路径、盲测任务清单和输出位置；不要继承包含预设答案的会话历史。每个用例最好使用新会话。当前批量测试允许同一代理顺序处理多例，存在跨用例影响，记录中应披露这一限制。

评测工具自身可用 `python eval/test_prepare.py -v` 验证，覆盖目录逃逸、旧目录保护、中文路径、盲测清单字段和文件改动检测。

建议记录：case_id、技能版本或哈希、模型与设置、日期、实际输出、通过/失败/未测、失败证据、耗时、Token（不可得时记 null）。不要用模型主观打分替代任务结果。

## 真实任务对照

另选约 20 个真实项目任务，在相同初始提交、环境、模型与设置下，分别提交原始需求和增强需求。两组隔离，顺序随机，使用相同的外部验收条件；条件不能由增强器自己定义。尽可能重复运行并保留失败样本。

分别记录功能完成率、返工轮数、越界修改、总耗时及总 Token。增强组的澄清、仓库读取、优化和执行成本全部计入；对照组也可正常澄清。任务完成率按事先定义的验收结果判定，不能把提示词更长当作改进。

先修复重复出现的具体失败，再考虑扩展产品。此版本尚未完成真实任务对照。
