## 方法与局限

- 首次继承会话历史的测试已中止，不计入上述数字。有效测试代理从空白历史启动，只提供 Skill、无答案任务清单及输出位置；各代理批量处理若干用例，仍存在跨用例影响。
- 主代理依据预设条件及技能整体约束逐条审阅实际输出，没有独立人工评审或自动语义判分。
- 回归包含 4 条原用例和 4 条新增用例；修复后没有重新运行全部原始 20 条。不存在“新版原始全套 20/20”结论。
- 只读测试由评测指令和技能共同约束，因此无意外写入不能单独归因于技能。另有授权执行用例确认它能继续执行简单明确任务。
- 未测试大型真实仓库、其他模型、所有工具组合、多轮长期会话、性能收益或自动技能选择。未记录可比较的 Token/耗时数据。
- 这些测试降低已覆盖问题的风险，不能证明无 Bug。下一步应在真实项目中收集失败案例和外部验收结果。

## 复现

在项目根目录执行（Python 路径按实际环境设置）：

```powershell
python eval/test_prepare.py -v
python eval/prepare.py eval/runs/<新批次>
python eval/prepare.py eval/runs/<回归批次> --cases eval/regression-cases.jsonl
python eval/prepare.py eval/runs/<批次> --verify
```

行为输出需要在新的代理会话中执行 tasks.json 指定的任务；脚本只负责生成 fixture 和检查文件变化，不自动调用模型或评判输出。
